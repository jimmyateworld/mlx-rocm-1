# K3(i) 2026-11-11: uniform small-M row-fused 4-bit QMV ("qmv class" rewrite) — gate report

Objective: rewrite the standard small-M 4-bit qmm "qmv class" kernel to eliminate the M=4 redundant weight decode using the proven wave-1 (e5ef5b7) pattern — LDS x staging + broadcast reads, weight tile decoded ONCE per (col, k-tile) and broadcast-MAC'd against all M rows, in-register RNE output, fewer barriers — then gate it in the fixed 4-stage order: (a) K2REG 1024 token identity, (b) per-GEMM flip audit, (c) standalone shape table (M4/M3 ratio must drop toward 1.0), (d) M4ROWEXACT preservation.

## Deliverable state (decisive)

- `qmv_rf_kernel.hip` (new module, 194 non-blank lines): the `qmv_rf_kernel`
  uniform M=1..4 row-fused kernel. Block (32,16) = 512 threads (1 thread = 1 col x 4 row slots), grid (ceil(N/16), ceil(M/4)); double-buffered LDS x staging (sx[2][4][1024] T); weight decoded once per (col, k-slice) into wn[32] and broadcast-MAC'd over all M rows; 1 barrier per k-slice; in-register RNE output cast; K%1024==0, 4-bit, bf16/fp16/f32.
- `qmm.hip`: one include + one dispatch block (inserted before the
  rows_ok gate, after the F3 statics). Gate: `MLX_QMV_RF=1 (DEFAULT OFF) && bits==4 && M<=4 && K%1024==0 && !((m4rexact || m4pref) && M==4)` — the F3 M4ROWEXACT / M4PREF record paths (M=4) run verbatim first in every configuration; MLX_QMV_NO_RF=1 forces the old ladder when RF is on.
- DEFAULT: OFF. The kernel ships for A/B via MLX_QMV_RF=1. Reason: gate (c) measured it ~45% slower than the existing defaults (below). The delivered lib (md5 9c376188, core dfc5906c unchanged) therefore behaves exactly like the base defaults on every path. Re-gated on the delivered default-OFF lib: K2REG 1024 token-identical (alltoks_md5 86d73662, 92.76 t/s = the 91.8 class), shape table = SoT behavior (N=248320: 947.1/1311.8/1693.4 us, M4/M3 = 1.291; N=12288: 1.155), M4ROWEXACT 0 row flips / 0 non-finite.

## Root cause (why the wave-1 pattern did not transfer)

1. The shared operand size differs. Wave-1 kqfg (GEMM class) stages
   weight tiles whose per-block stream far exceeds L1 (file-GEMM, many 256-value tiles per block) — there the LDS double-buffer is the win. In QMV the shared operand is x, which is M<=4 x K<=12288 <= 96 KB bf16: L1/L2-resident across all blocks. The rows_msg "re-dequant" it removes is a pure ALU chain over an L1-cached 16B load — cheaper than the LDS round-trip it is replaced with.
2. The replacement cost: per block-slice the RF kernel writes 8 KB to LDS
   (512 threads x 4 rows x 1024 T), reads it back, and pays 1 barrier; 4 k-slices x 16 waves = 64 barriers per block; at N=248320 that is 15,520 blocks x ~64 MB of LDS traffic and 64 barriers — on top of a 512-thread (16-wave) block that is 4x the thread count of rows_msg's 192-thread (6-wave, 24-col) design.
3. The M4/M3 super-linearity: M=4 adds one more row to the per-slice
   fetch (33% more LDS write) and one more row of 32 FMA on top of the already-heavy per-block fixed cost, so the ratio went to 2.61 at lm_head instead of toward 1.0.

Conclusion: the "16x redundant dequant" in rows_msg is real but cheap on this hardware; LDS staging + barriers is the more expensive path for QMV-class operand sizes. The decode hoist (t1334) is also a loss (x re-read 4x from L2 costs more than the decode ALU saved). The existing defaults (rows_msg base, mr2/mr3, per-row wide) stand; the RF kernel is retained default-OFF for A/B (bit-identical and token-identical, so it is a safe experiment arm).

## Next-step recommendation (operator)

The M4/M3 ratio on the large-N band is already near-linear (1.15-1.17 this session, 1.29 R1) and below the 4/3 = 1.333 ideal-linear ceiling; the remaining M=4-specific cost is the 33% extra row work, not redundant dequant. Further wins require a block-morphology change (F3's M4PREF 3-wave split is the current best M=4 arm at 1.153), not another dequant-staging variant.
